# QwenWave — веб-DAW (Digital Audio Workstation)

Полноценная многодорожечная студия в браузере: запись микрофона с мониторингом в
эффектах, MIDI/Piano Roll, библиотека из 195 сэмплов, 18 встроенных эффектов +
пользовательские плагины, питч-коррекция вокала, мастеринг и офлайн-экспорт в WAV.

Всё работает на **Web Audio API + AudioWorklet + IndexedDB**, без внешних CDN и
без сборки — открывается как есть.

---

## Быстрый старт

```bash
python3 serve.py          # → http://localhost:8000
```

Нужен современный браузер (Chrome/Edge/Firefox/Safari 16.4+).
`localhost` даёт secure-context: микрофон, AudioWorklet и IndexedDB работают.
Для доступа с других устройств поднимите https-прокси — микрофон требует TLS.

При первом запуске создаётся демо-проект (5 дорожек, лупы, MIDI-мелодия, готовые
FX-цепочки), чтобы всё было слышно сразу: нажмите **Space**.

## Что реализовано (по вашему ТЗ)

| Требование | Реализация |
|---|---|
| Аудио- и MIDI-дорожки | Кнопки **+ Аудио / + MIDI**; MIDI-дорожка = сэмплер (питч-маппинг любого сэмпла) или встроенный поли-синтезатор (unison, фильтр с огибающей, sub, вибрато, glide). Полифония с voice-stealing и release-фейдом (без щелчков). |
| Запись микрофона + слышать себя | Дорожка ● (arm) → **MON**. Мониторинг идёт отдельной цепочкой **через те же плагины** с аппаратной задержкой (~5–20 мс). Кнопки **WET/DRY** сравнивают «с эффектами / без». Вход: gain, high-pass, noise-gate, метр и спектр в реальном времени. |
| Библиотека звуков (не процедурная в рантайме) | **195 настоящих WAV-ассетов** в `library/packs/` (77 МБ): барабаны, 808/Reese/Acid-басы, лиды, клавиши, пэды, хор/струны, FX-переходы, IR-импульсы реверба, вокальные тоны + **60 лупов с меткой BPM** (авто-warp под темп проекта). Манифест с пиками/RMS/тональностью/BPM. Кэш декодированных буферов в IndexedDB с LRU (лимит 260 МБ). Свои сэмплы — перетащить файлы/папку (хранятся в IndexedDB). |
| Прописывать мелодии | **Piano Roll**: рисование/выбор/ластик, resize, velocity-линия, квантование, привязка к гамме проекта, транспонирование, аккорд из ноты, дублирование, прослушивание, автоскролл к нотам. MIDI-вход с клавиатуры/контроллера тоже пишется. |
| Различные звуки/семплы/лупы | Браузер сэмплов: поиск, фильтры (лупы/one-shot/темпроект/тональность), деревья паков, превью-волны, drag&drop на дорожку, дабл-клик — добавить. |
| Темп проекта | BPM 20–400 (поле, TAP-tempo, drag с Shift), размер 4/4·3/4·6/8…, тоника+лад. Темп меняется «на лету» без скачка позиции; лупы с меткой BPM автоматически warp-ятся. |
| Сохранение проекта | Автосейв в IndexedDB + ручное сохранение; список проектов во вкладке «Проекты»; переносимые файлы **`.qwp`** (JSON + встроенные записи) и **`.qwpz`** (ZIP со всеми сэмплами) — открываются перетаскиванием. |
| Экспорт | Офлайн-рендер (быстрее реального времени) полного микса или **стемов**; 16/24/32-bit WAV с TPDF-dither; нормализация до −0.3 dBTP; замер **LUFS (ITU-R BS.1770)**, peak/RMS в таблице результата + вердикт по громкости. |
| Мастеринг | Мастер-шина: HP20 → ваши инсерты → **мультибэнд-компрессор → стерео-имейджер → сатуратор → brickwall-лимитер** (всё в AudioWorklet, sample-accurate). 6 пресетов (Balanced/Loud/Radio/Warm/Vocal/Clean) + Amount; диалог «Мастеринг» с анализом и рендер-замером. |
| Свои плагины | Хост поддерживает **WAM 2.0**, **AudioWorklet-плагины**, **JS-SDK QwenWave** и WASM-сборки — они исполняются нативно в браузере. Нативные `.dll/.vst3/.component/.so` **не могут** исполняться в песочнице браузера: формат определяется по заголовку, плагин регистрируется как «bridge», к дорожке применяется встроенная эмуляция (звук не пропадает), а для настоящей работы приложен локальный мост `tools/plugin_bridge/bridge_server.py` (pedalboard + WebSocket). |
| Обработка вокала/мелодий плагинами | FX-цепочка на каждой дорожке (порядок, bypass, перетаскивание слотов). Пресеты «Vocal → Radio Lead / Telephone / Auto-tune / Doubling». Отдельно: **питч-коррекция** (YIN-детект тона → ноты → квантование в гамму → гранулярный ретюн, недеструктивно) и **извлечение мелодии в MIDI**. |
| Оптимизация | Look-ahead-планировщик (22 мс тик / 180 мс вперёд) с чанкованием длинных клипов; метры из worklet-тэпов одним rAF-циклом (не AnalyserNode на канал); shared convolver на все ревербы одного IR; LRU-кэш буферов и waveform-спрайтов; коалесинг перерисовки аранжировки через rAF; voice-stealing с лимитом полифонии; заморозка дорожек в аудио. |

## Архитектура

```
index.html ─ src/main.js ─ src/ui/app.js (оболочка, хоткеи, автозагрузка сессии)
                    │
   src/core/store.js            состояние проекта, шины событий, undo/redo (снапшоты)
   src/effects/defs.js          18 эффектов: параметры → автогенерация UI + фабрики нод
   worklet/processors.js        DSP на аудиопотоке: limiter, multiband, imager, saturator,
                                gate, de-esser, verb, chorus, pitch-shift, meter + 3 плагин-процессора
   src/engine/engine.js         AudioContext, мастер-шина, графы дорожек (input→fx→pan→trim→out)
   src/engine/transport.js      семпл-точный планировщик, луп, метроном, audition
   src/engine/instruments.js    сэмплер (питч-кэш LRU) + поли-синтезатор
   src/engine/library.js        IndexedDB-кэш библиотеки, импорт, пики, ProjectStore
   src/engine/recorder.js       getUserMedia, мониторинг, MediaRecorder→тейк, MIDI-вход
   src/engine/pitchcorrection.js  YIN → сегменты нот → PSOLA-ретюн, time-stretch
   src/engine/pluginhost.js     WAM/AudioWorklet/JS-плагины, детектор нативных форматов, ZIP-unpack
   src/engine/exporter.js       офлайн-рендер, WAV (dither), LUFS/peak/RMS
   src/engine/persistence.js    автосейв, .qwp, .qwpz (ZIP), миграции
   src/ui/*                     аранжировка, piano roll, микшер, FX-рейк, браузер, панели
```

**Почему это не «лагает»:** аудио планируются заранее по времени AudioContext,
поэтому джанк главного потока (отрисовка 40+ дорожек) не влияет на звук; DSP живёт
в AudioWorklet (отдельный поток); всё тяжёлое (рендер, анализ тона, ZIP) — офлайн/асинхронно.

## Плагины: как подключить свой

См. `assets/plugins/sdk/README.md`. Три рабочих пути в браузере:

1. **JS-плагин** — файл с `export const meta` + `export (async) function create(ctx, params, host)`.
   Перетащите `.js` в панель «Плагины». Пример с собственным AudioWorklet: `sdk/example-plugin.js` (Auto-Wah).
2. **AudioWorklet-плагин** — папка/`.zip` с `processor.js` (+`manifest.json`).
3. **WAM 2.0 / WASM** — стандартные веб-бандлы.

Готовые примеры в комплекте: **QW Tape Warmth**, **QW Vocal Strip** (появляются в FX-рейке).

Нативные VST/DLL: браузер физически не исполняет машинный код с диска. QwenWave
честно определяет формат по сигнатуре, объясняет это в диалоге «Как подключить
VST/DLL», держит звук дорожки встроенной эмуляцией и прикладывает мост-сервер
(`tools/plugin_bridge/bridge_server.py`) для настоящей работы через локальный процесс.

## Регенерация библиотеки и тесты

```bash
.venv/bin/pip install numpy scipy
.venv/bin/python tools/synth_lib.py     # перепечь 195 WAV в library/packs + manifest.json

.venv/bin/pip install playwright && .venv/bin/playwright install chromium
python3 serve.py --no-browser &          # в одном терминале
.venv/bin/python tests/smoke.py          # загрузка без ошибок консоли
.venv/bin/python tests/functional.py     # play, рендер, питч, плагины, сохранение, перф
```

Тесты гоняют реальный Chromium (headless, fake-mic) и падают при любой ошибке консоли.

## Известные ограничения (честно)

- Нативные VST3/AU/DLL не исполняются в браузере (песочница) — только WAM/WASM/JS или локальный мост.
- Микрофон и AudioWorklet требуют secure-context (`https://` или `localhost`).
- MP3-энкодер не встроен (экспорт в WAV); при желании подключается lamejs одним файлом.
- Safari < 16.4: часть AudioWorklet может деградировать на нативные ноды (приложение предупредит).

Лицензия библиотеки: royalty-free, используйте в своей музыке свободно.

## Деплой на сайт (GitHub Pages и др.)

Приложение **полностью статическое** — Python/Node на сервере не нужны, `serve.py`
используется только локально. GitHub Pages даёт HTTPS, а это ровно то, что нужно
микрофону и AudioWorklet, так что на хостинге студия работает даже лучше, чем дома.

### GitHub Pages (пошагово)
```bash
# 1) в папке проекта
git init
git add .nojekyll index.html styles.css serve.py server.cjs start.bat package.json README.md
git add src worklet assets library tools
git commit -m "QwenWave web DAW"

# 2) создайте пустой репозиторий на github.com, затем
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```
3) На странице репозитория: **Settings → Pages → Build and deployment → Source:
   Deploy from a branch → Branch: `main`, folder `/ (root)` → Save.**
4) Через 1–2 минуты откройте **https://USERNAME.github.io/REPO/** — студия работает,
   микрофон разрешён (HTTPS).

Почему это работает без правок:
- все загрузки (`library/…`, `worklet/…`, `assets/…`) — **относительные**, поэтому
  сайт живёт и в корне домена, и в подпапке `/$REPO/`;
- `.nojekyll` отключает обработку Jekyll, чтобы Pages отдал файлы как есть;
- сэмплы тянутся **лениво** (только те, что реально используются) и кэшируются в
  IndexedDB, поэтому посетитель не скачивает все 77 МБ сразу.

### Особенности / советы
- Репозиторий с библиотекой ≈ 77 МБ — это нормально для Git (лимит на файл 100 МБ не
  превышен). **Не используйте Git LFS**: GitHub Pages не раздаёт LFS-контент.
- Если пуш слишком тяжёлый или нужна «лёгкая» версия: удалите `library/packs/**`
  перед коммитом — тогда библиотека стартует пустой, а пользователи перетаскивают
  свои сэмплы (функциональность не ломается, просто нет фабричных лупов в демо).
- Альтернативы Pages: **Netlify / Vercel / Cloudflare Pages** — перетащите папку в
  их интерфейс (drag&drop deploy). Учтите лимит трафика бесплатного тарифа: ленивая
  загрузка сэмплов его сильно экономит.
- На Pages IndexedDB/автосохранение привязаны к домену сайта: проекты, сохранённые
  локально, не переедут на сайт автоматически (и наоборот) — это нормально.
